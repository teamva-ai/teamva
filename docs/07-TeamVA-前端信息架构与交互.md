# Teamva 前端信息架构与交互

## 1. 技术与产品边界

- Svelte 5、TypeScript、Vite、TanStack Query；
- 浏览器与桌面构建始终使用同源 `/v1`，没有远端构建 profile；
- 业务请求只走同源 HTTP 和 Run 事件流，不通过 Wails binding 调领域方法；
- 支持简体中文、繁体中文、英语、日语、德语、法语、西班牙语、葡萄牙语和俄语；
- 首次语言跟随操作系统，用户主动选择后优先使用本机偏好；
- 用户外观支持浅色、深色和跟随系统；七套全局配色默认使用 `default`，可独立自定义背景、强调色和控件色，修改即时生效并自动保存。配色统一应用于整个工作台，项目不再定制颜色或提供「跟随项目」，切换项目不替换语义颜色 token；详见 [全局外观与配色](APPEARANCE.md)。

## 2. 导航

项目内容：

- 概览：项目名称、备注、任务、计划任务、资源和项目记忆摘要；
- 任务：任务列表、状态、描述、评论、Agent 会话和确认请求；
- 资源：代码目录、资料目录和 URL；
- 项目记忆：约束、决定、事实和进展；
- 计划任务：创建、编辑、预览、立即运行、暂停和运行记录。

本机：

- Agent：左侧选择，右侧原位创建或编辑；
- Skills：左侧本机已安装，右侧 Skills 商店；
- 编程工具：Codex/OpenCode 状态、版本和诊断日志。

设置和活动记录固定在导航底部。项目内容与本机之间不放分割线。

## 3. 概览与原位编辑

- 概览按一条统计带和下方内容列表展示，不拼成四张仪表盘卡片；
- 项目名称与备注在鼠标悬停后可点击编辑；
- 编辑态背景透明，只显示文本光标；
- `Enter` 保存单行标题，`Escape` 取消；
- 摘要条目点击后跳到对应导航页。

任务标题使用同样的原位编辑方式。

## 4. 任务详情

- 左侧是紧凑任务列表，右侧是当前任务；
- 顶部清楚区分标题、状态、创建者、创建时间和评论数；
- 状态只提供“进行中、已解决、已关闭”；
- 任务描述与全部评论组成一个竖向内容流，头像位于内容行内；
- 相邻回复之间只用一条横线，不使用彼此分离的卡片和大间距；
- 用户发出带 `@Agent` 的评论后，每个 Agent 立即显示“正在工作”占位；
- 每次结构化 @ 创建独立会话；再次 @ 同一 Agent 也不会复用上一次会话；
- 点击 Agent 评论或底部会话标签打开对应侧栏。

## 5. Agent 会话侧栏

- 侧栏从右侧覆盖打开，左边缘可拖动宽度，双击恢复默认宽度；
- 拖动时只改变视觉宽度，结束后再持久化，避免连续布局和存储写入；
- 内容区禁止横向滚动，长命令和路径在内部换行或截断；
- 连续流式 chunk 合并成一条助手消息；工具事件独立显示；
- 上下文整理显示开始和完成状态；
- 底部输入框支持继续追问当前会话；
- “修正评论”位于发送按钮左侧，问号内部区域悬停时才显示说明；
- 内部控制消息只在当前侧栏出现，不显示成公共任务评论。

确认按钮只在 Codex/OpenCode 主动请求时出现。已结束、已取消或已拒绝的请求只显示结果，不再展示可操作按钮。

## 6. Agent 与 Skills

Agent 页面使用左右布局。右侧表单包含名称、备注、软件、模型、提示词和 Skills；创建与编辑不打开弹窗。
模型留空时使用对应编程工具的默认模型。

普通 Agent 与系统 Agent Lumi（可改名，如 Roomie）共用同一表单；编辑入口统一为 `/agents?agent=<id>`，其他页面只链接到此处。字段只改变草稿，公共「保存」提交配置、修订和 Skills，不自动保存。系统 Agent 不显示删除操作，并保持启用；不另做一套只允许修改 Provider/模型的助手表单。Lumi 的普通 Issue/定时任务能力与普通 Agent 一致；只有工作记录、灵感等全局助手入口的 Run 仍受只读授权限制。

所有 Agent 的该页表单均可打开模型供应商弹窗，只有显式点击测试才发送一次 Hello。保存供应商仅把 OpenCode 与模型引用选入当前 Agent 草稿，仍需公共保存。首次引导仅「CLI 检测 → 认识 Lumi」两步并前往此页，不内嵌配置或 API 第三步。

Agent Skills 只能从“本机已安装 Skills”选择。每个条目都保留名称和描述，支持按钮操作与左右拖动；
已绑定项可排序。页面提供“管理本机 Skills”入口，并明确说明未安装的 Skill 不能绑定。

本机 Skills 页面同样左右排列：

- 从商店拖到已安装区域会开始真实安装，按钮在完成前显示 loading；
- 安装的是完整制品，不创建空目录或占位 `SKILL.md`；
- 已安装条目可重新安装、打开目录或卸载；
- 商店和已安装条目使用同一套名称与描述。

## 7. 资源和编程工具

代码目录的“打开”菜单根据当前操作系统与已安装应用显示 Finder/资源管理器/文件管理器、终端、
VS Code 和 Zed。终端与编辑器使用资源目录作为工作目录。

编程工具诊断使用弹窗展示实际步骤、结果、耗时和必要的技术日志。列表文案只回答三个问题：是否可用、
版本是什么、上次什么时候检查；详细协议名只留在诊断日志里。

### 项目记忆创建

新建项目记忆只填写标题、类型和内容；标题与类型共用 `FieldGroup[data-field-group="memory-identity"]`，内容位于下方，不显示 Key 输入或隐藏输入。UI 每次打开新草稿时使用 `uuid.v4()` 生成 `memory-<UUIDv4>` 并在内部持有；失败重试复用该草稿的 Key，成功、取消或切换项目后重置，新草稿使用不同 Key。内部 Key 不计入未保存修改，关闭未编辑的弹窗不弹确认。

已有记忆的 Key 仍在列表和版本信息中只读展示，长 Key 必须换行或截断而不撑宽布局；编辑、归档和恢复不改变 Key。这里只简化用户创建表单，API 的 Key 必填和唯一约束、Agent 使用语义 Key 的行为均保持不变，不需要后端重启。

## 8. 视觉与可用性

- 右侧页面占满可用空间，不套额外大卡片、外阴影或无意义外边距；
- 卡片仅用于确实独立的对象或弹层；列表主要用横线分隔；
- 按钮、链接、输入框和 select 使用统一的自定义 `focus-visible` 焦点环，不能以移除系统 outline 为由隐藏键盘焦点；状态不能只依赖颜色；
- macOS 红绿灯与拖动区、品牌和状态栏保持安全间距；
- 外层窗口使用操作系统原生装饰和圆角，不写死半径；
- Modal 和 SideSheet 支持 Escape，焦点不会落到遮罩后的页面；
- 最小窗口为 1040×680，并补做窄屏 Web 回归。

表单实现统一使用 [`web/src/ui`](../web/src/ui/README.md)，业务页面不直接新增原生 `input/select/textarea`。桌面单行控件使用 32/36/40px 尺寸，粗指针触摸目标至少 44px；Select 箭头距右边 12px，尺寸与状态集中维护。Modal 统一处理焦点圈定、背景 inert、关闭后焦点恢复和嵌套栈；Field 自动关联主控件，辅助控件显式 `inheritField={false}`；ISO datetime 使用 DatePicker 的时区转换并保留秒/毫秒，不切字符串截断。

## 9. 验收

- 所有导航页均能在真实 `.app` 中打开，无遮挡、横向滚动或多余空白；
- 项目、资源、Agent、Skills、任务、项目记忆和计划任务能完成各自主要操作；
- Codex/OpenCode 诊断显示真实安装、登录和模型探测结果；
- 同一任务中重复 @ 同一 Agent 会得到多个独立会话；
- 侧栏有真实流式输出、工具事件、上下文整理和原生确认状态；
- 重启应用后项目数据、设置和侧栏宽度恢复；
- 不依赖开发服务器、固定端口或外部 Teamva 服务。
