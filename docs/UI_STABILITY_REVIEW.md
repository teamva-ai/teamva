## 已修复

| 场景 | 原因 | 修复与回归 |
| --- | --- | --- |
| 点击当前记忆后草稿消失 | `select` 无条件清除 dirty，触发重新载入服务器正文 | 使用独立编辑基线计算 dirty，同条目点击不重置编辑器 |
| 记忆刷新后历史列表突然收起 | 干净编辑器每次重填字段都关闭历史 | 只在更换记忆时关闭历史；同条目版本刷新保留展开状态 |
| 保存记忆期间继续输入，下一次保存冲突或草稿被回写 | dirty 与查询数据互相影响，保存返回未同步当前草稿的版本基线 | 请求捕获条目、编辑会话和内容；只有对应会话的成功响应推进基线，不覆盖请求发出后的输入 |
| 其他客户端更新记忆时本地草稿的冲突保护 | 草稿不能直接采用查询缓存中的最新版本号 | dirty 时保留原版本，仍由服务端拒绝并发冲突；仅本人的成功保存可推进该草稿版本 |
| Agent 保存后先移到末尾再跳回来 | 本地缓存用 filter+append，随后 GET 恢复按创建时间排列 | 已存在条目原位替换；新增条目才追加 |
| Agent 修订加载时整个表单上下移动 | 在表单上方插入、移除块级 Loading | 状态图标使用头部既有图标位置，编辑 fieldset 标记 aria-busy 并保持禁用保护 |
| 设置保存返回时覆盖新选择或新输入 | 成功回调直接覆盖当前 locale/theme/token 字段 | 按提交快照和已同步基线比较，只更新没有被继续编辑的字段；新令牌草稿不显示已保存提示 |
| 关闭弹窗时焦点恢复带动背景滚动 | 调用 opener.focus() 使用默认滚动行为 | 恢复焦点使用 preventScroll，保留既有嵌套弹窗栈和键盘圈定 |
