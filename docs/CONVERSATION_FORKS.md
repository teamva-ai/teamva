# 图对话分叉语义

## 一次分叉：冻结前缀 + 两条可写分支

以源节点 `S` 中一条已发布 Agent 消息 `B` 为界，在一个事务内净新增两个节点：

- **冻结父副本 `P`**：位于源节点原来的位置、接入原父链，`locked=true`。继承 `S` 原有的
  `inherited_messages`，只复制本地消息的前缀（含 `B`），保留正文、状态、Run 关联、消息版本与时间；
  副本消息使用新 ID，不新建或伪造历史 Run。
- **完整延续分支 `S`**：原 ID 不变，挂到 `P` 下并设置 `locked=false`。全部原消息（含 `B` 后的多轮
  已发布、失败等消息）、消息 ID/版本/时间、Run 关联、节点状态、AgentRevision 和继承快照均不改写。
  不用“复制后删除源”的方式替代，避免断开历史执行关联。
- **新前缀分支 `C`**：挂到 `P` 下，`locked=false`，本地消息为空；继承快照为 `S` 原有快照 + 本地截至
  `B` 的已发布消息。不会把失败占位当成成功回复。API 返回 `C`，详情接口同时可见 `P/S/C`。

两条分支都可通过公共发送接口继续。发送时，`S` 的 Run 读取 **原有继承快照 + 全部本地已发布消息**；
`C` 的 Run 读取 **前缀快照 + C 自己后续发布的消息**，而不是动态遍历父链。失败消息仍保留供查看，
但失败回复不进入模型上下文；已发布的失败轮用户输入仍按既有规则进入完整延续上下文。
嵌套分叉不重复拼接祖先快照。上下文仍受现有 256 KiB 上限约束，超限发送显式失败，不静默丢尾部。

同 Agent 的新分支沿用源 AgentRevision，改选 Agent 时使用所选 Agent 当前 revision；不改变 Provider
隔离、只读/禁工具设置，每次 Run 仍使用独立 native session。

## 冻结源、布局与事务边界

已冻结的节点也可再次分叉。新的 `P` 冻结，原冻结源 `S` 成为可写完整延续；`S` 的既有后代仍挂在
`S` 下，仅整体平移。它们的锁定状态、上下文和 Run 均不改动，活动后代不会被打断。

三者都继承源节点**数据库中持久化**的宽高，不使用默认 `380×560`。布局以实际 border box 计算，
两条子分支同列、相对父副本上下对称；整体平移原子保留旧子树相对位置，避开同图其他可见节点，
不移动已删除节点或其他图。不修正原先人为造成的重叠；不得引入新的碰撞。坐标超限时全量回滚。

源节点的活动 Run 和未结束目标（active/paused/blocked/budget_reached，包括两轮间隙）均阻止分叉。
跨用户、其他节点消息、用户消息、失败/未发布/已删除消息不能作为边界。事务内重新校验源及边界，
并发发送先成功则分叉因忙碌拒绝；分叉先成功则发送进入完整延续源。并发删除遵守删除版本锁，
并发分叉串行读取最新子树。节点/消息插入、移动、解锁、图版本和工作记录任何一步失败均回滚。

## 旧软删尾部：只读判断与恢复风险

分叉实现仅改变后续操作，不修改 SQL 基线；程序不会在启动时迁移、回填、解锁旧业务节点或自动恢复旧消息。针对已误隐藏记录的一次性恢复必须取得用户对明确范围的授权，不新增通用恢复接口。

仅从代码可确认：旧分叉曾按 `(created_at, id)` 软删边界之后的消息，同时改写这些行的 `updated_at`；
删除整图和删除子树同样会写 `conversation_messages.deleted_at`。表中没有专用删除原因或分叉事务 ID。
因此，不能仅凭 `deleted_at` 唯一归因为分叉，更不能全表清空该字段。仍存活节点下的软删后缀、
边界顺序、同一操作时间和父副本/工作记录可提供较强旁证，但重复分叉、后续删除、旧版本或人工写入
会改变证据；当前父链也未必能一对一还原每次历史分叉。旧代码覆盖过的原始 `updated_at` 不能单靠
该行准确恢复，不能伪造其时间、版本或 Run 成功状态。

如用户另行授权恢复，应先对一致性快照/副本做只读候选清单，逐节点核对消息顺序、完整 Run 归属、
父链与工作记录，并排除合法删除及活动 Run/目标；优先在隔离副本验证，再由用户确认明确消息 ID
范围和目标节点。恢复会改变模型后续实际上下文，可能触发上下文上限，也可能意外复活用户删除的
内容；不能以“界面看起来齐全”代替上下文与历史关联验收。没有足够证据时保留原库，不实施自动修复。

## 画布滚轮

- 桌面上，指针位于任一节点卡片外时，普通竖向滚轮直接按指针所在位置缩放，不需要 Ctrl/Command；缩放范围仍为20%–200%，平移继续使用空白处拖动或键盘。
- 指针位于节点卡片内时，画布不拦截滚轮，由消息区、输入框等原生滚动区域处理；消息区设置滚动链约束，到达边界不触发画布缩放。
- 窄屏保持节点纵向排列与原生滚动，不启用桌面画布滚轮缩放。
