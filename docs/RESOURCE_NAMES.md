# 网址资源自动命名

创建网址资源时，`name` 可省略、为空或仅含空白。HTTP 层先验证项目所有权，再尽力读取 HTML `<title>`；实体只解码一次、空白合并，名称最多 200 个 Unicode 字符。手填非空名称仅去掉首尾空白，绝不发起取名请求；创建完成后没有后台改名任务。目录创建及现有重命名仍要求非空名称，Store 与 SQL 基线不变。

取名失败、超时、非 HTML、无标题或受安全限制时仍可创建资源：显示名称退回去除 query、fragment 的网址并截断到 200 字符，避免将分享 token 复制进名称及工作记录。资源地址本身仍保留这些部分。取消创建请求会停止取名且不插入资源；不会保存抓取正文，也不记录抓取错误或访问网址细节。

取名使用独立的 4 秒 HTTP(S) 客户端，最多 4 次重定向、32 KiB 响应头、512 KiB 原始及解码内容预算；找到标题即停止，不执行 JS、不加载子资源、不使用代理、Cookie 或用户会话头。禁止凭据 URL、HTTPS 降级、localhost、私网、链路本地、metadata、保留/特殊用途地址、IPv4-mapped IPv6 及非公共 IPv6 范围。每跳检查全部 DNS 地址，实际拨号再次校验并绑定 IP，核对连接对端，避免重绑定。内网地址仍能登记为元数据，只跳过自动取名。此策略不改变其他请求的网络行为。

确定性后端测试仅使用私有依赖注入、内存网络管道和临时 SQLite，不依赖真实公网、Provider 或已有应用数据；没有生产策略旁路开关。
