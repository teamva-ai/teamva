# 首次配置引导与编程 CLI 设置

## 使用

- 「设置 → 编程 CLI」新增标签页：检测本机编码 CLI 的安装、登录与模型状态，手动运行诊断，并可「重新运行引导」。
- 「编程工具」独立页面保留，两处共用同一个检测面板，行为一致。
- 首次使用且仍为空（没有用户创建的 Agent，且 Lumi 未配置）时，引导以**全屏半透明遮罩 + 居中弹窗**覆盖在应用之上：
  - 从默认入口（根路径 / 工作台）进入会自动打开弹窗；
  - 直接打开具体子页面（链接/书签）不打断，顶部显示可点击的提示条，点击后在同一页面打开弹窗；
  - 设置 → 编程 CLI 的「重新运行引导」也在当前页面打开弹窗；`/onboarding` 是别名，会归一化到工作台并打开弹窗；
  - 遮罩点击不会关闭弹窗，只能「暂时跳过」或完成。
- 严格两步：编程 CLI 检测（按检测状态自动并发补测）→ 认识 Lumi，完成后进入任务 `/issues`，不自动跳转 Lumi 配置；引导不提供配置表单、不自动保存配置、不创建其他 Agent，也没有可选 API 第三步。
- 可随时「暂时跳过」；跳过或完成后服务端记忆，只有设置里的「重新运行引导」会再次打开。中途直接关页未点跳过时，下次从默认入口仍会自动弹出。

## 判定与持久化

- `needed` 是推导值，不持久化：没有用户创建的 Agent（`system_role <> 'general'`、未删除）**且** Lumi 未配置（无 `current_revision_id`）时为 true。项目是否存在不影响判定。
- `dismissed` 持久化在 `app_metadata`（键 `onboarding:<userID>`，仅存布尔值），跳过或完成时置 true，手动重开不做服务端改动。
- 接口：`GET /v1/system/onboarding` → `{dismissed, needed}`；`PUT /v1/system/onboarding` `{dismissed}`。契约见 OpenAPI。

## 检测与提示

- 诊断仍由既有 `/programming-tools/:provider/diagnose` 执行（安装、版本、服务、登录、模型），只读、不自动安装、不执行命令。
- provider.json 新增 `install_hint`、`login_hint`、`docs_url`，由仓库维护文案；注册表由 `pnpm generate:providers` 生成，Go 侧 `Metadata` 校验长度与 URL 协议。
- 面板在未安装/未登录/未检测时展示对应提示与官方文档链接；引导第一步只对**尚未就绪或从未检测**的 CLI 自动并发检测：已连接（ready+authenticated）的 CLI 复用存储结果，来回切步或重开引导不会重复全量诊断，需要重检可点「诊断」。检测期间状态列显示「正在诊断…」。

## Lumi 与公共 Agent 配置

- 第二步介绍内置 Agent Lumi：它不可删除并保持启用，可像普通 Agent 一样配置、参与 Issue 和定时任务。工作记录与灵感入口另有独立的只读会话范围，不因此扩大 Lumi 作为普通 Agent 的能力。需要时可自行从 Agents 页面编辑配置；引导完成并不代表 Lumi 已配置或模型已连接，也不依赖 Lumi 配置查询成功才能完成。
- Lumi（包括改名为 Roomie 等名称后）与普通 Agent 共用 `/agents?agent=<id>` 的名称、备注、Provider、模型、提示词和 Skills 表单。工作记录、灵感和引导不保留配置副本。
- 所有字段均为草稿，只有公共「保存」通过 `PATCH /v1/agents/{id}` 才生效；不使用独立 `PUT /v1/work-assistant`。用户提示词和 Skills 实际传入 Run，全局助手入口仍强制只读工具作用域。系统 Agent 不可删除，当前底层也禁止禁用。
- 模型可从建议中点选或自由输入，留空使用对应 Provider 默认值。未配置 Lumi 的 Agent 草稿优先内置 OpenCode，模型留空；不覆盖已有配置，也不自动持久化默认值。保存不要求 CLI ready，实际对话仍要求可用服务。
- 内置 CLI 不等于保证可用模型或免费额度，不伪造已认证状态；可在 Agent 页添加自己的模型 API。

## Agent 页的模型供应商弹窗

- 所有 Agent（不仅是 Lumi）均可从 Agent 页打开「添加大模型供应商」，不属于引导第三步。提供 OpenAI、Anthropic、Google Gemini、DeepSeek、阿里云百炼/Qwen、Moonshot/Kimi、智谱/GLM、OpenRouter 与 OpenAI 兼容接口。预设 API 地址和示例模型可编辑，模型是否可用以用户账号为准。
- 测试按钮仅在显式点击时向所填端点发送一次固定 `Hello`，不保存草稿、不重试、不跟随重定向；超时 25 秒、响应最多 64 KiB，要求有效模型回复，200 HTML 或错误 JSON 不算成功。可能产生供应商费用，界面提前提示。
- 保存供应商后将模型映射到 `teamva-<preset>/<model>`，仅把内置 OpenCode 与该引用选入当前 Agent 草稿，不自动提交 Agent；仍需公共「保存」才改变 Agent 配置。凭据使用本机 OpenCode 配置目录中的独立 `teamva-model-providers.json` 私有 0600 文件，不覆盖原有 `opencode.json(c)` 或 `auth.json`，不进 app.db、Runtime 命令 inbox、API 响应、审计正文或诊断导出；仅本机入口可配置和测试，要求登录、CSRF 与同源。
- 空密钥仅在供应商与完整 API 地址未变时复用；更换地址必须重新输入，避免把旧密钥发给新主机。HTTP 仅允许本机 loopback，其他地址要求 HTTPS，拒绝 URL 凭据、查询串及 fragment。
- 引导的「进入任务」把引导标记为完成并打开 `/issues`；「暂时跳过」返回工作台。创建第一个项目仍在工作台侧栏完成。

## 当前基线与验证

- 引导本身不新增数据表，只使用既有 `app_metadata`；当前构建仍遵守仓库的数据库基线检查规则，旧基线拒绝启动，不自动迁移或清库。
- 自动化范围：store 推导/持久化、HTTP 公共 Agent 保存与旧配置路由移除、OpenAPI 契约、前端两步引导/跳过记忆/完成进入任务、供应商保存仅更新草稿，以及公共保存与只读 Run 配置传递；真实浏览器需覆盖设置标签页、提示条、默认入口弹窗与公共表单流程，不能用历史验收代替当前版本证据。
