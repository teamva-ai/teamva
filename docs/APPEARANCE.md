# 全局外观与配色

## 使用

「设置 → 常规 → 外观配色」提供七套完整配色：默认（`default`）、奶油炭黑（Hallmark）、纸白极简（Chamber）、复古纸墨（Flexoki）、雾海蓝、鼠尾草绿、鸢尾紫。各配色都有浅色/深色版本，并支持原有的跟随系统模式。默认配色沿用官网与 Silken 图标的绿色体系，但按明暗调整亮度：浅色主按钮、开关和选中强调使用低饱和深绿 `#52763a`，按钮配白字，画布 `#fbfbfb`、卡片 `#ffffff`、文字 `#09090b`，强调文字用深绿 `#426523`；深色保留品牌绿 `#c2ff75`、画布 `#111114`、卡片 `#18181b`、文字 `#fafafa`。图标和官网品牌色不变，大面积背景保持中性，不铺满荧光绿。

- 选择卡片、主题或语言立即生效并自动持久化，无需「保存设置」按钮；刷新、切换页面或重开应用仍保留。
- 自定义背景色、强调色、控件色在拖动中即时预览，不因停顿或短暂去抖反复保存；结束选择（change）或失焦后统一提交最终色。切换设置 Tab、SPA 离页或卸载也会提交待保存的最终预览；重复 change/失焦及拖回当前有效色不产生额外请求或日志。
- 设置使用串行合并队列；保存期间继续编辑不会被较早响应覆盖。离页先完成保存，失败保留草稿并明确重试；版本冲突需刷新确认，不静默覆盖外部新值，也不悄悄回滚到旧外观。
- 配色应用于整个工作台，切换项目不改变外观；不再提供「跟随项目」，项目创建与编辑也不再定制配色。
- 每套配色都有独立控件色，可分别自定义强调色、背景色和控件色。控件色驱动主按钮、开关、复选框，并从卡片底色派生轻微着色的输入底色、边框、悬停、焦点与前景色，不与强调色绑定。Input/Textarea 显式移除原生外观；自动填充裁掉 Chromium 强制底色并保留主题文字，不使用阴影覆盖。原生下拉弹层与日期弹窗仍由系统绘制，页面内控件、箭头与选项底色使用主题。背景会联动表面、悬停、边框、阴影与文字；强调色与可读强调文字分离。极端颜色会适度修正，保证可读性；原生控件和代码高亮跟随实际背景的明暗，而非在深背景上强行显示浅色控件。
- 「恢复默认颜色」清除自定义色但保留所选预设；卡片支持方向键、Home/End 和单一 Tab 焦点。

## 实现约定

- 预设与颜色算法：`web/src/lib/appearanceThemes.ts`；完整 token 类型、基础预设与 CSS 映射统一位于 `web/src/lib/themeTokens.ts`，不再使用 `ProjectTheme` 或项目主题模块，也不增加第二份页面私有配色逻辑。
- 全局设置：`UserPreferences.appearance = { palette, accent?, background?, control? }`；`palette` 为 `default|hallmark|chamber|flexoki|ocean|forest|iris`，默认 `default`。每套明暗预设包含独立 `control`，派生 `controlHover/controlText/controlSubtle/controlBorder/controlFocus`，对应统一的 `--color-control*` token。
- `PATCH /v1/me/preferences` 复用 `expected_version`；省略 appearance 时保留，提供时整对象替换。服务端只接受上述七个预设与六位 `#RRGGBB`，包括 `control` 在内的自定义颜色可为空以清除；拒绝 `project`、未知字段、null 和非法颜色。
- 按用户保存在既有 `app_metadata` 的 `user_appearance:<userID>` 中，与 preferences 更新共用事务与版本锁。不修改数据库基线、不迁移旧库，不把用户偏好存成项目配置。
- 旧存 `appearance.palette=project` 仅在读取时投影为 `default`，保留自定义强调色、背景色和控件色；读取、重开或未修改 appearance 的偏好更新不回写投影，不因投影增加版本或修改元数据时间。其它已存全局预设和用户自定义色保持原值，不批量重置。
- Project 领域模型、创建/编辑请求与公开 API 响应均不含 `theme`。物理 SQLite `projects.theme` 旧列保留原基线，不迁移、不清理；仅新建项目写固定遗留占位满足既有 schema，项目读取/更新不再用它决定配色，也不因全局外观变化回写该列。
- `theme.ts` 负责唯一的根 token 写入。待保存显示由 owner token 管理，队列保存成功后以新持久化值接管；系统配色变化同时更新实际页面与卡片预览。
- 三种颜色的 `input` 仅更新本地草稿与即时预览，不进入持久化队列，不增加偏好版本或 `user.preferences_updated` 审计；`change`（即使此前没有 input）、失焦及离页边界再合并提交最终色。与当前有效色相同的草稿丢弃，change + blur 去重；保留原有串行保存、错误重试、冲突确认和离页 flush，不修改服务端审计或清理既有记录。
- 新增主题须包含完整的背景/表面/边框/正文/强调/控件/状态/代码/图表/阴影 token，不能只替换 accent。全局配色的主要文字与表面至少满足 4.5:1，高对比 ink/canvas 至少 7:1；主按钮的 controlText/control 至少 4.5:1，控件边框与输入底色至少 3:1。输入焦点仍遵守无 Outline/外圈规则，不以新增控件色恢复 ring 或 box-shadow。
- 默认正文在 body 显式使用 `--color-text`，标题、列表与浮层继承当前主题。用户对话在浅色中保留 `ink` 底色配 `canvas` 前景；实际暗色中（含自定义暗背景）使用 `surfaceHover` 近黑底配 `text` 浅色文字，默认 `#27272a` 比卡片 `#18181b` 稍亮，继承消息与用户头像保持一致，禁止反成大块白底。其它反色头像与提示仍用 `ink/canvas`。RichText 的反色粗体、行内代码、表格与引用继承同一前景，弱底色和分隔线由 currentColor 派生；表头单元格透明并使用 thead 底色，独立深色代码块仍用白字。禁止通过全局强制白字覆盖主按钮的 `controlText`。
- 顶栏不再展示 Coding CLI 名称、版本或就绪状态，右侧留空；审批提醒与功能帮助位于左侧品牌旁，保留原有权限、确认流程与首次演示行为。CLI 详情仍在设置和 Agent 配置中查看。
- 任务时间线中普通评论与 Agent 协作评论统一使用 `surface` 底色，机器人头像使用 `surfaceSubtle/textSecondary`，不再用绿色背景区分作者；工作分配子卡片保留中性层次，状态语义与操作行为不变。
